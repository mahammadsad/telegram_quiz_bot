# Audit remediation decisions

This log records material assumptions and tradeoffs made while applying the 20 August 2026 audit without an available operator.

| Decision | Rationale | Consequence / follow-up |
|---|---|---|
| Treat the same-origin Render application as the canonical topology. | The API already serves the frontend and authenticated workflows require a trusted API origin. | `PUBLIC_APP_URL` and `PUBLIC_API_BASE_URL` are identical in `render.yaml`. A deployment owner must provision and verify that service. |
| Keep GitHub Pages only as a base-path-safe preview. | Pages cannot perform Telegram-authenticated scoring against itself. Removing it would discard a useful static preview; presenting it as production would be deceptive. | Relative assets, navigation, manifest and worker work under a subpath, but release docs explicitly exclude Pages from production acceptance. |
| Fail readiness when canonical URLs are absent or non-HTTPS. | A green application with no declared public ownership reproduces P0-01. | Local/development operators must set explicit HTTPS values when exercising production readiness. |
| Preserve legacy quiz submission compatibility but never trust legacy timing. | Immediately rejecting old Mini App clients would create an avoidable outage; trusting their duration preserves the ranking flaw. | Legacy official attempts may have null/untrusted duration. New clients call the server start lifecycle. |
| Define independent model verification as a different provider/model identity, not a second prompt. | Repeating the same model does not establish independent evidence. | Same-model questions need authoritative evidence, deterministic proof or human approval; otherwise publication fails closed. |
| Treat an authoritative source or deterministic proof as evidence even without a second model. | Independent evidence can be stronger and more reproducible than another model opinion. | Evidence bases and both model identities are persisted for audit. Subject-specific proof coverage is still incomplete. |
| Do not fabricate reserve questions, production replay outcomes or current-affairs breadth. | These are high-stakes content/data operations requiring reviewed material and production access. | P0-02/P1-03/P2-01 remain partial/external despite reliability code fixes. |
| Remove AdSense rather than loosen CSP. | The loader had no placement and third-party script on authenticated/timed pages would enlarge the privacy boundary. | Advertising can return only through a separately reviewed, consented, isolated design. |
| Publish privacy and terms only as clearly labeled drafts. | Controller identity, contact details, jurisdiction and retention decisions are owner/legal facts the repository does not establish. | Placeholders must be replaced and reviewed before the pages are represented as final legal policy. |
| Gate account-deletion processing behind backup/legal release approval. | The migration includes a grace period and deletion processor, but running it against production is irreversible user-data mutation. | Apply the additive schema safely, but do not schedule `process_due_account_deletions` until backup/restore and policy scope are verified. |
| Use additive, forward-only migrations and no down migration in production. | Removing new columns/functions can break old/new app versions and destroy evidence. | Application rollback is supported; database rollback is forward repair or disabling new entry points. |
| Stop on a remote migration-history mismatch. | The production ledger has versions that are absent from Git; marking them reverted or treating later files as applied without independently proving equivalence could corrupt schema history or replay non-idempotent changes. | The learner-report projection remains unapplied until the missing historical migrations are recovered or reconciled through a reviewed maintenance procedure. |
| Do not choose a license. | Repository ownership and intended code/content rights are not documented. | The owner must explicitly select an OSI license and separately state question/source content rights. |
| Do not enable a paid scheduler, deploy production, alter Telegram settings, replay real jobs, send notifications or change branch protection automatically. | Those require external ownership, billing, real-user coordination, or missing credentials; production gates are not green. | Exact owner actions are in the release runbook and status matrix. |
| Keep the Render `free` plan declaration unchanged. | Changing billing or claiming an always-on SLA without authorization violates the task safety boundary. | P1-05 remains an explicit platform-owner decision. |
| Leave architecture refactoring incremental. | Combining a large router/frontend rewrite with integrity migrations would increase regression and review risk. | New logic is placed behind focused services/repositories; monolith reduction remains future work. |
