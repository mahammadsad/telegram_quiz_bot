# Security policy

## Supported version

Security fixes are applied to the latest commit on `main`. Older deployments are unsupported.

## Reporting a vulnerability

Do not open a public issue for a vulnerability or include learner data, credentials, Telegram init data, database URLs, or screenshots containing private information.

Use GitHub’s private vulnerability-reporting feature for this repository. If it is unavailable, contact the repository owner through the private address configured in the GitHub profile. A dedicated security contact is still an owner action; see `docs/AUDIT_REMEDIATION_DECISIONS.md`.

Include the affected commit, reproduction steps using synthetic data, impact, and a suggested mitigation. Expect an acknowledgement within three working days. No response-time promise is made until an operational security owner is named.

## Safe-harbor intent

Good-faith research that avoids privacy violations, service disruption, social engineering, credential access, production-data mutation, and public disclosure before remediation is welcome. This statement is not legal advice or authorization to access systems you do not own.
